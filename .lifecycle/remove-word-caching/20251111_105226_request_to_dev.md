## Assignment: Fix Critical Infinite Recursion Bug in Actor Conversion

**Context:**

Runtime testing discovered a **CRITICAL BUG** in the MushafDatabase actor conversion (commit 936c7d4). The app crashes immediately on startup with an infinite recursion loop.

**Bug Details:**

**Root Cause:** Circular dependency causing infinite recursion:
1. `ContentView.calculateMinimumPageWidth()` calls `shouldShowTwoPages` (ContentView.swift:2235)
2. `shouldShowTwoPages` calls `PageModeManager.shouldShowTwoPages()` (ContentView.swift:456)
3. `PageModeManager.shouldShowTwoPages()` calls back to `calculateMinimumPageWidth()` (PageModeManager.swift:31-32)
4. **Result:** Infinite loop → stack overflow → crash

**Stack Trace Evidence:**
```
frame #10: calculateMinimumPageWidthSync(pageNumber=589, pageWords=0 key/value pairs)
  → shouldShowTwoPages.getter (line 2235)
    → PageModeManager.shouldShowTwoPages (line 456)
      → calculateMinimumPageWidth(pageNumber=590)
        → [repeats infinitely until crash]
```

**Critical Observation:** `pageWords=0 key/value pairs` (EMPTY dictionary) - This confirms the database initialization race condition that code review warned about.

**When Bug Occurs:** Upon app startup (first page load)

**Impact:** App is completely unusable - crashes before any UI appears

## Root Cause Analysis

This bug is caused by the **database initialization race condition** identified in code review (.lifecycle/remove-word-caching/20251110_163915_response_from_review.md, lines 230-276):

**The Problem:**
```swift
// MushafDatabase.swift:10-18
private init() {
    self.layoutDB = nil
    self.wordsDB = nil
    // Databases opened asynchronously AFTER init completes
    Task {
        await self.openDatabases()
    }
}
```

**What Happens:**
1. Actor init completes immediately with databases still `nil`
2. First page load calls `getPageWords()` before databases finish opening
3. Guard statements return empty array (silent failure)
4. Empty `pageWords` dictionary triggers unexpected code path
5. This code path contains circular dependency → infinite recursion → crash

**Why This Wasn't Caught Earlier:**
- Build verification: ✅ Passed (compiles successfully)
- Code review: ⚠️ Identified theoretical risk but approved for runtime testing
- Automated tests: ❌ Failed due to unrelated infrastructure issue
- Manual testing: **First time running the app** → discovered immediately

## Required Fix

Implement **synchronous database initialization** as recommended by code review (response lines 258-265).

**Option 1 (Recommended): Synchronous Database Opening**

```swift
// MushafDatabase.swift
public actor MushafDatabase {
    public static let shared = MushafDatabase()

    private var layoutDB: OpaquePointer?
    private var wordsDB: OpaquePointer?

    private init() {
        self.layoutDB = nil
        self.wordsDB = nil
        // Open databases SYNCHRONOUSLY before init completes
        self.openDatabasesSync()
    }

    private func openDatabasesSync() {
        // Open layout database
        if let layoutPath = Bundle.main.path(forResource: "uthmani-15-lines", ofType: "db") {
            if sqlite3_open(layoutPath, &layoutDB) != SQLITE_OK {
                print("Error opening layout database")
            } else {
                print("Layout database opened successfully")
            }
        }

        // Open words database
        if let wordsPath = Bundle.main.path(forResource: "uthmani", ofType: "db") {
            if sqlite3_open(wordsPath, &wordsDB) != SQLITE_OK {
                print("Error opening words database")
            } else {
                print("Words database opened successfully")
            }
        }
    }

    // Remove the async openDatabases() method entirely
    // Keep closeDatabases() for cleanup (see also: fix deinit - separate issue)
}
```

**Why This Works:**
- Databases open **before** init completes
- All subsequent method calls have valid database connections
- No race condition possible
- Database file opening is fast (< 100ms) - acceptable in init

**Alternative (Not Recommended):** Initialization gate pattern - adds complexity without benefit for this use case.
