## Assignment: Fix Critical Thread Safety Issue in MushafCache

The review team found a **CRITICAL thread safety violation** in the immediate cache clearing implementation that must be fixed before this feature can proceed to testing.

**Problem:**
While `clearWordCache()` correctly uses `loadQueue.sync` to synchronize access to the `allWords` dictionary, the `getWords()` method reads and writes to `allWords` without any synchronization. This creates a race condition.

**Race Condition Scenario:**
1. User is actively viewing Quran (main thread calls `getWords()`)
2. User toggles Cache Quran Data to disabled (UI thread calls `clearWordCache()`)
3. Thread A reads `allWords[id]` at line 123 (unsynchronized)
4. Thread B executes `allWords.removeAll()` at line 176 (synchronized but conflicts with A)
5. Thread A tries to write `allWords[word.id] = word` at line 139
6. **Result:** Concurrent dictionary access → potential crash or data corruption

Swift dictionaries are not thread-safe. **All accesses to `allWords` must be wrapped in `loadQueue.sync`.**

**Required Fixes:**

1. **Fix cache lookup in getWords() (lines 122-128):**
   ```swift
   // Wrap the cache read in loadQueue.sync
   if let cachedWord = loadQueue.sync(execute: { allWords[id] }) {
       return cachedWord
   }
   ```

2. **Fix cache write in getWords() (line 139):**
   ```swift
   // Wrap the cache write in loadQueue.sync
   loadQueue.sync {
       allWords[word.id] = word
   }
   ```

**Optional Enhancement:**
Consider changing `allWords.removeAll()` to `allWords.removeAll(keepingCapacity: true)` in `clearWordCache()` to avoid memory reallocation if the user re-enables caching during the same session.

**Also Fix Documentation:**
In your response, correct the statement "Uses `removeAll()` to clear the dictionary while preserving allocated capacity" - this is inaccurate. `removeAll()` does NOT preserve capacity; only `removeAll(keepingCapacity: true)` does.

**Testing After Fix:**
After making these changes, build the project and verify:
1. Build succeeds with no errors
2. The synchronization pattern is consistent across all `allWords` accesses
3. No new thread safety issues introduced
