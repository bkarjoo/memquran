## Assignment: Fix .test/README.md Based on Review Team's Findings

**Context:**

We updated `.test/README.md` to add mandatory automated testing requirements. The review team analyzed it and found **critical loopholes, logical contradictions, and writing quality issues** that make it ineffective. Your job is to fix it.

**The Problem We're Solving:**
Testers were skipping automated tests (build verification, running existing tests) and immediately declaring "blocked" requesting manual testing. We need the README to actually prevent this behavior.

**Review Team's Verdict:**
"Will this prevent testers from skipping automated tests? **NO**."

**What Went Wrong:**
1. **CRITICAL LOOPHOLE:** Template allows "SKIPPED" status - tester can skip automated tests and still be compliant
2. **Logical contradictions:** "Phase 2: MUST DO FIRST" (illogical), blocking policy contradicts itself
3. **Missing scenarios:** Zero tests, non-Xcode projects, investigation scope undefined
4. **Hostile tone:** Defensive language ("is NOT an excuse"), feels like punishment not documentation
5. **Excessive redundancy:** "MANDATORY" appears 8 times
6. **Poor structure:** 68-line template embedded (43% of document)

**Your Task:**

Fix `.test/README.md` by implementing the review team's recommended changes. See `.plan/response.md` (the review) for complete analysis.

**Priority Fixes (MUST DO):**

1. **Remove SKIPPED option** (line 107):
   - Change `[SUCCESS/FAILURE/SKIPPED with reason]` to `[SUCCESS/FAILURE]`
   - Add: `**If FAILURE:** [root cause: build failure / test failures / environment issue]`

2. **Fix Phase 2 naming** (line 28):
   - Change "MUST DO FIRST" to "COMPLETE BEFORE MANUAL TESTING"

3. **Rewrite blocking policy** (lines 69-80):
   - Make clear: "Blocked" means you TRIED Phase 2 but failed, NOT that you skipped it
   - Require 15-minute investigation for build failures
   - List valid blocking reasons with proof requirements

4. **Add Phase 1.5: Project Assessment** (after line 27):
   - Check if project has automated tests
   - Check if Xcode project (if not, coordinate with planner)
   - If zero tests exist, document and recommend what should exist

5. **Remove defensive tone** (lines 49, 77-79):
   - Replace hostile language with professional statements
   - Remove "Invalid blocking reasons" section (state requirements positively)

6. **Define investigation scope** (line 41):
   - Set 15-minute time limit
   - Specify what to document: error messages, failing components, root cause determination

**Additional Improvements:**

7. Reduce "MANDATORY" from 8 occurrences to 2-3 maximum
8. Consider shortening or restructuring the embedded template (lines 86-153)
9. Add guidance for zero-test scenarios
10. Add guidance for non-Xcode projects (or state it's Xcode-only)
